Time budget is flexible. Suggested starting point: 60–90 minutes on weekdays and 2–3 hours Saturday. These are placeholders, not commitments. On busy weeks, reduce scope instead of removing rest.

What makes a sprint complete?

UnderstandExplain the idea and when NOT to use it.
DemonstrateOne working example plus tests for a failure case.
Show evidenceA small PR with diagram, tradeoffs, and actual observations.

First week · Nov 16–22

Monday: inventory current PPT AI features and mark implemented vs planned. Tuesday: trace a real chat request. Wednesday: draw a diagram of chat → gateway → model and any REST/tool path. Thursday: run one structured-output or tool-call experiment. Friday: record gaps and tests. Saturday: package findings in a small documentation PR. Sunday: rest.

Scope rule: Don't rebuild features already working. Prefer product engineering, context quality, evaluations, agent safety, and usable UX. Advanced model serving, Kubernetes, and custom gateway infrastructure are optional, not core requirements. Dates and deliverables are targets, not proof that features have shipped.
